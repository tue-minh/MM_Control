# AGENTS.md

Repository for an STM32F407VET6 motion-control board (MM_Control).
Three top-level areas:

- `firmware/` — STM32CubeMX-generated C firmware (FreeRTOS + USB CDC).
- `hardware/` — KiCad project (`MM_Control.kicad_pro`, schematics, PCB, library).
- `Gerber/` — fabricated Gerber/zip outputs for manufacturing.

The build system, source list, and pin/peripheral config are all generated by STM32CubeMX. Treat generated files as the source of truth and keep CubeMX `USER CODE` regions intact when editing by hand.

## Firmware layout

- `firmware/CMakeLists.txt` — top-level project (`MM_control` executable). User code hooks go into the empty `target_sources` / `target_include_directories` / `target_compile_definitions` blocks.
- `firmware/CMakePresets.json` — `Debug` and `Release` presets. Default generator is Ninja; default toolchain is `cmake/gcc-arm-none-eabi.cmake`.
- `firmware/cmake/stm32cubemx/CMakeLists.txt` — authoritative source list. If you add a new `.c`/`.s`/`.h`, append it to `MX_Application_Src` or `MX_Include_Dirs` here, not in the top-level CMakeLists.
- `firmware/STM32F407XX_FLASH.ld` — linker script used by both toolchains.
- `firmware/startup_stm32f407xx.s` — vector table / reset handler. Already listed in `MX_Application_Src`.
- `firmware/MM_control.ioc` — STM32CubeMX project file. Edit peripheral/pin config here, then re-generate.
- Application code lives in:
  - `firmware/Core/Inc` / `firmware/Core/Src` — `main.c`, `freertos.c`, `gpio.c`, `can.c`, `i2c.c`, `spi.c`, `tim.c`, `usart.c`, `stm32f4xx_it.c`, `stm32f4xx_hal_msp.c`, `stm32f4xx_hal_timebase_tim.c`, `system_stm32f4xx.c`.
  - `firmware/USB_DEVICE/App` — `usb_device.c`, `usbd_desc.c`, `usbd_cdc_if.c` (CDC class callbacks: `CDC_Transmit_FS`, `CDC_Receive_FS`, `CDC_Init_FS`).
  - `firmware/USB_DEVICE/Target` — `usbd_conf.c` (low-level USB FS HAL glue).
- `firmware/Drivers/` — CMSIS + STM32F4 HAL/LL. Do not edit; rebuild via CubeMX if a peripheral is missing.
- `firmware/Middlewares/Third_Party/FreeRTOS/Source` — FreeRTOS kernel + `portable/GCC/ARM_CM4F`. Heap is `heap_4.c`. CMSIS-RTOS2 wrapper at `Middlewares/.../CMSIS_RTOS_V2/cmsis_os2.c`.
- `firmware/Middlewares/ST/STM32_USB_Device_Library` — USB device core + CDC class. Do not edit.

## Build commands

All commands run from `firmware/`. Requires `arm-none-eabi-gcc` (or `starm-clang` for the clang path) on PATH, plus `cmake` ≥ 3.22 and `ninja`.

GCC ARM (default presets):

```
cmake --preset Debug
cmake --build --preset Debug
cmake --preset Release
cmake --build --preset Release
```

Artifacts land in `firmware/build/Debug/` or `firmware/build/Release/` (`MM_control.elf`, `MM_control.map`). The map file is added to `cmake clean` automatically.

ST ARM clang (alternative toolchain — not wired into a preset):

```
cmake -S . -B build/clang -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=cmake/starm-clang.cmake \
  -DCMAKE_BUILD_TYPE=Debug
cmake --build build/clang
```

The clang toolchain defaults to `STARM_TOOLCHAIN_CONFIG=STARM_PICOLIBC`; edit `cmake/starm-clang.cmake` to switch to `STARM_NEWLIB` or `STARM_HYBRID`.

For flashing/debugging, no script is checked in — use `arm-none-eabi-gdb`, OpenOCD, or STM32CubeIDE against the produced `.elf`.

## Application entrypoint and runtime shape

- `Core/Src/main.c` — `HAL_Init` → `SystemClock_Config` (HSE 8 MHz, PLL 168 MHz, `FLASH_LATENCY_5`) → peripheral `MX_*_Init` → `osKernelInitialize` → `MX_FREERTOS_Init` → `osKernelStart`. Never returns; the only FreeRTOS task `defaultTask` runs the USB device init in `freertos.c:118` and then idles in `osDelay(1)`. Add new threads/queues/mutexes inside the `USER CODE` regions of `MX_FREERTOS_Init`.
- `Core/Src/stm32f4xx_it.c` — IRQ handlers (USB, CAN, USART, EXTI, etc.).
- HAL time base is TIM14 (`stm32f4xx_hal_timebase_tim.c`); do not change `HAL_InitTick` to Systick without updating the time-base source.
- `Error_Handler()` disables IRQs and spins — surfaced by HAL failures, invalid configs, and `assert_failed` (`USE_FULL_ASSERT`).
- USB CDC is the only host-facing interface. Host traffic goes through `USB_DEVICE/App/usbd_cdc_if.c`; user callbacks must live inside the `USER CODE` sections of that file.

## Conventions and gotchas

- `USER CODE BEGIN …` / `USER CODE END …` markers are the only safe edit regions in CubeMX-generated files. Anything outside them is overwritten on regen.
- C11 is required (`firmware/CMakeLists.txt:11`); the CubeMX CMakeLists errors out if `CMAKE_C_STANDARD` is 90 or 99.
- MCU is `STM32F407VET6` (LQFP100). `Mcu.IP0..Mcu.IP15` in `MM_control.ioc` lists the active peripherals: CAN1, FREERTOS, I2C1, SPI1, SPI3, TIM1, TIM3, TIM4, TIM9, USART1, USART2, USB_DEVICE/USB_OTG_FS. If you add a peripheral, update both the `.ioc` and the source list in `cmake/stm32cubemx/CMakeLists.txt`.
- CAN bus is configured for 875 kbit/s in the `.ioc`; matching termination is on the PCB.
- FreeRTOS uses `heap_4.c` — fragmentation-resistant but no `vPortFree()` of NULL is allowed; rely on standard `malloc`/`pvPortMalloc` patterns.
- The build emits `compile_commands.json` (top-level CMakeLists sets `CMAKE_EXPORT_COMPILE_COMMANDS TRUE`) for clangd/IDE indexing.
- There are no tests, no linter, no formatter, and no CI workflows in this repo. `git status` will only show what you touch.
- No `.gitignore` is present — be careful not to commit `firmware/build/`, `MM_control.elf`, `MM_control.map`, or CubeMX backup files (`*.bak`, `*.tmp`).
