# User Taste
- User develops on Windows and uses PowerShell (prompt shows `PS D:\...`); prefer PowerShell syntax for shell commands and Windows-style paths (e.g., `python examples\stepper_demo.py COM7`, backslash separators). Confidence: 0.85
- Prefers interactive scripts/consoles that start running first, then let the user type/pick options (menus, prompts) at runtime — rather than requiring all arguments up front before the program runs. Confidence: 0.75
- Expects documentation (e.g. protocol docs, READMEs) to be kept in sync with code changes — when behavior/interfaces change, update the docs as part of the same task rather than leaving them stale. Confidence: 0.7
- Expects related code layers to stay consistent when interfaces change — e.g. when rewriting a firmware driver, also consider whether the Python host client (python/tue_acsi) needs updating, rather than treating layers in isolation ("update all"). Confidence: 0.8
- Drives the whole firmware build/flash cycle through VS Code tasks (`.vscode/tasks.json`) rather than ad-hoc CLI commands: delete the old build, rebuild, convert ELF→BIN, then flash via USB DFU (`dfu-util`). Treat tasks.json as the canonical build/flash entry point. Confidence: 0.6
- Prefers the agent to carry a multi-step plan through to completion autonomously rather than pausing to ask for confirmation between steps; gets impatient with requests like "do the rest task!!!" / "have you done yet" when work is left unfinished. Confidence: 0.6
- Wants complete implementations with full parity to the referenced library — when porting/adapting a library, expose ALL of its functionality (every instruction, every API surface, e.g. SYNC_READ, RESET_TURNS, whole register map) rather than a partial subset; states this emphatically ("IMPLEMENT ALL THE CODE RELATED TO ..."). Confidence: 0.7
- When a reference implementation is provided, wants the rewrite to faithfully follow its architecture and design patterns (e.g. restructuring a monolithic driver into the reference's layered regs/protocol/hal design) rather than keeping the old structure. Confidence: 0.7
- Expects new firmware modules/drivers to be actually wired into the RTOS task setup (e.g. `freertos.c`) and runnable, not just compiled — asks how to "run it" when a module isn't invoked from the task layer. Confidence: 0.55
